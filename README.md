# AODV и OLSR в NS-3.49

Учебный проект по безопасности маршрутизации в самоорганизующихся сетях. В симуляторе сравниваются AODV и OLSR при четырёх видах нарушений. Для каждой пары «протокол и нарушение» подготовлен отдельный патч.

| Вид нарушения | AODV | OLSR |
| --- | --- | --- |
| Чёрная дыра | Есть патч | Есть патч |
| Серая дыра | Есть патч | Есть патч |
| Туннель | Есть патч | Есть патч |
| Сивилла | Есть патч | Есть патч |

## Из чего состоит проект

- **Патч (`.patch`)** содержит изменения в исходном коде протокола. В папке `patches/` восемь патчей для моделей нарушений и два для контрольных сценариев.
- **Эталон** — штатный AODV или OLSR из чистого NS-3.49. Для сравнения используются два штатных протокола из одной версии симулятора.
- **Сценарий моделирования (`.cc`)** задаёт число узлов, их расположение, связность, трафик и параметры прогона. Контрольные сценарии находятся в `patches/tests/`, общий сценарий сравнения — в `patches/experiments/`.
- **Скрипты проекта** помогают подготовить рабочую копию и обработать результаты. Описание устройства каждой модели хранится рядом с патчами.

[Чистые исходники NS-3.49](https://gitlab.com/nsnam/ns-3-dev/-/tree/ns-3.49)

## Контрольные сценарии

[Патч AODV](patches/ns3-49-aodv-baseline.patch) и [патч OLSR](patches/ns3-49-olsr-baseline.patch) добавляют по сценарию в `scratch/` чистого NS-3.49. Оба используют линейную топологию и один поток UDP между крайними узлами. По умолчанию в сети три узла, а передача 20 датаграмм начинается на 20-й секунде.

В примере пути `~/kursovai` и `~/ns-3.49` указывают на локальные копии репозитория и симулятора.

~~~bash
cd ~/ns-3.49
patch -p1 < ~/kursovai/patches/ns3-49-aodv-baseline.patch
patch -p1 < ~/kursovai/patches/ns3-49-olsr-baseline.patch
./ns3 configure --enable-modules=aodv,olsr,wifi,mobility,applications --disable-python-bindings
bash ~/kursovai/run-baseline.sh "$PWD" aodv
bash ~/kursovai/run-baseline.sh "$PWD" olsr
~~~

Скрипт принимает параметры сценария после имени протокола. Например, обоим запускам можно передать `--nodes=5 --packets=12 --start=25`. В выводе `sent` — число отправленных датаграмм, `received` — число принятых, `pdr_percent` — доля доставленных в процентах.
