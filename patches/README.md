# Патчи AODV и OLSR для NS-3.49

В папках [AODV](aodv/) и [OLSR](olsr/) по пять патчей. Имя файла указывает на протокол и вариант.

| Вариант | Что изучаем в симуляции |
| --- | --- |
| `baseline` | Доставку пакетов при штатной маршрутизации |
| `blackhole` | Потерю транзитных пакетов, затронутых моделью чёрной дыры |
| `grayhole` | Выборочное отбрасывание транзитных пакетов |
| `wormhole` | Влияние туннеля на маршруты и доставку |
| `sybil` | Влияние нескольких сетевых идентификаторов одного узла на маршрутные таблицы |

Патч определяет модель поведения. Сценарий моделирования задаёт число узлов, их расположение, связи и трафик. [Короткие сценарии](../simulation/checks/) проверяют отдельные случаи. [Общий сценарий](../simulation/comparison/) использовался для сравнения двух протоколов в одинаковых условиях.

## Три режима туннеля

В сравнительных испытаниях для обоих протоколов использовались одинаковые по смыслу режимы.

| Режим | Что проходит через туннель | Что показывает прогон |
| --- | --- | --- |
| Контроль | Туннель отключён. Доступны обычные связи сети. | Сколько пакетов доставляется при исходной связности |
| Служебный | Служебные кадры и ARP. Пользовательские UDP-датаграммы через туннель не проходят. | Как изменяется доставка, если меняются сведения о маршрутах |
| Полный | Служебные кадры, ARP и пользовательские данные | Какая часть данных доставляется через туннель и как меняется задержка |

В служебном режиме счётчик UDP-датаграмм **через туннель** равен нулю. Общая доставка при этом может быть выше нуля, если часть пакетов дошла обычным путём. В полном режиме высокий процент доставки сам по себе не показывает, каким путём шли пакеты. Поэтому в отчёте отдельно указаны общая доставка и количество датаграмм, доставленных через туннель.

Контроль в таблице — прогон в общей схеме сети с отключённым воздействием. Патч `baseline` добавляет отдельный короткий пример со штатной маршрутизацией. У этого примера своя линейная топология.

[Методика и результаты сравнительных испытаний](https://github.com/wtfus1n/kursovai/blob/oldmian/results/matched-5040/README.md#результаты-на-решётке-из-100-узлов)

## Какие условия меняет сценарий

- **Число узлов и топология.** Линия, решётка, треугольник и кольцо описывают размещение и связность сети. Эти варианты относятся к разным сценариям.
- **Трафик.** Число датаграмм и время начала передачи влияют на то, что успевает измерить прогон.
- **Повтор.** Чтобы сравнить AODV с OLSR, для каждой пары прогонов сопоставляют топологию, число узлов, потоки и номер повтора. Так меньше риск принять разницу в условиях за разницу между протоколами.

## Как поменять условия эталонного прогона

После [подготовки NS‑3.49 и применения эталонных патчей](../README.md#запуск-эталонов) из корня этого репозитория можно запустить оба протокола с одинаковыми параметрами. Замените `$HOME/ns-3.49` на путь к своей копии симулятора.

~~~bash
bash ./run.sh "$HOME/ns-3.49" aodv --nodes=5 --packets=12 --start=25
bash ./run.sh "$HOME/ns-3.49" olsr --nodes=5 --packets=12 --start=25
~~~

| Параметр | Что меняет в эталонном сценарии |
| --- | --- |
| `--nodes` | Число узлов в линии, от 3 до 20 |
| `--packets` | Число UDP-датаграмм |
| `--start` | Время начала передачи в секундах, от 1 до 3600 |

`run.sh` запускает эталонный сценарий выбранного протокола. По умолчанию в линии три узла, отправляются 20 датаграмм, передача начинается на 20-й секунде. В строке результата `sent` — отправлено, `received` — доставлено, `pdr_percent` — процент доставки.
